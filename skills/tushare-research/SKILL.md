# Tushare A股投研分析

基于 Tushare Pro 数据的 A 股深度投研分析框架。

## 研报框架概览

```
宏观分析 → 基本面分析 → 消息面分析 → 技术面分析 → 投研结论 → Agent 强制搜索迭代补充
```

| 章节 | 内容概要 |
|------|----------|
| **一、宏观分析** | 1.1 市场走势（A股+行业指数）；1.2 政策分析（**【待补充】**） |
| **二、基本面分析** | 2.1 商业模式；2.2 竞争格局；2.3 市场预期 |
| **三、消息面分析** | 3.1 近期公告汇总；3.2 机构研报（**【待补充】** 研报观点汇总、隐藏线索挖掘）；3.3 行业个股新闻 |
| **四、技术面分析** | 4.1 技术指标（脚本输出）；4.2 视觉分析（**【需 Agent 手动补充】**） |
| **五、投研结论** | **【需 Agent 手动撰写】**：多维验证、交易预案、操作建议、风险提示 |
| **六、数据来源与免责声明** | 接口标注、免责声明 |

## 使用方法：生成研报完整流程

### 1. 用脚本生成研报框架

运行 `research_report.py` 生成初版研报（**以脚本实际输出为准**），可能需要几分钟：

```bash
python3 scripts/research_report.py <股票代码> [日期YYYYMMDD] [--save-md]
```

示例：

```bash
python3 scripts/research_report.py 000001.SZ
python3 scripts/research_report.py 600519.SH 20260302
python3 scripts/research_report.py 688585.SH --save-md
```

- `--save-md`：将**初始生成的研报**写入 `raw_reports/<代码>_深度研报_<日期>.md`。

#### 报告章节（与脚本输出一致）

| 章节 | 小节 | 说明 |
|------|------|------|
| **一、宏观分析** | 1.1 市场走势（日期） | 大盘走势、行业指数、宏观关注点 |
| | 1.2 政策分析 | 最新政策动态表 + **【待补充】** 政策目标、短中期影响、对公司影响 |
| **二、基本面分析** | 2.1 商业模式深度解析 | 主营业务表、盈利能力表 + **【待补充】** 盈利模式、产业链、五维评估 |
| | 2.2 竞争格局全面评估 | 行业格局表、同业对比表 + **【待补充】** 护城河、竞争分析验证 |
| | 2.3 市场预期深度分析 | 估值水平、预期拆解 + **【待补充】** 市场预期待搜索验证 |
| **三、消息面分析** | 3.1 近期公告汇总 | 公告列表 + **【待补充】** 公告汇总分析 |
| | 3.2 机构研报 | 研报明细 + **【待补充】** 研报观点汇总、隐藏线索挖掘 |
| | 3.3 行业个股新闻 | 近期新闻表 + **【待补充】** 新闻汇总分析 |
| **四、技术面分析** | 4.1 技术指标分析（基于数据计算） | technical_analysis 输出 |
| | 4.2 视觉分析（基于K线图解读） | **【需 Agent 手动补充】** |
| **五、投研结论** | — | **【需 Agent 手动撰写】** |
| **六、数据来源与免责声明** | 数据来源汇总、免责声明 | 脚本自动输出 |

### 2. 逐项补全【待补充】内容

脚本在报告中会打出占位与提示，以下九项**必须由 Agent 或人工在报告生成后补充**，未补充不得视为可交付的完整报告：

| 位置 | 脚本中的提示 | 补充要求 |
|------|----------------|----------|
| **1.2 政策分析** | `【待补充】` 政策目标、适用时间、短期/中期影响、对公司的具体影响 | 基于初稿中「最新政策动态」表，使用 `kimi_search` 补充；须包含：政策目标、适用时间、短期/中期影响、对公司的具体影响 |
| **2.1 商业模式深度解析** | `【待补充】` 盈利模式定位、产业链、商业模式五维评估 | 结合给出的「建议搜索」关键词，使用 `kimi_search` 补充：盈利模式定位（结合行业特性）、产业链上下游、五维评估（费用结构、产业链话语权、现金流健康度等） |
| **2.2 竞争格局全面评估** | `【待补充】` 护城河与竞争壁垒、竞争分析待验证 | 按脚本「护城河与竞争壁垒」表中的建议搜索关键词，网络搜索补充：特定客户源、技术/专利壁垒、客户粘性、差异化定位；验证细分竞争对手、产业链关系、市场份额 |
| **2.3 市场预期深度分析** | `【待补充】` 市场预期待补充（需搜索验证） | 按脚本「市场预期待补充」表中的建议搜索关键词，使用 `kimi_search` 验证：机构一致预期、订单/产能、概念/题材、估值锚定、业绩催化剂；须标注可信度（✅已验证/⚠️待验证/❓未证实） |
| **3.1 近期公告汇总** | `【待补充】` 公告汇总分析 | 基于「公告列表」及链接，重点分析：重大合同/订单、募集资金变更、资产收购/出售；高管变动、董事会/股东会决议、股权激励；诉讼/问询、业绩说明、分红送转；结合公司业务与行业判断对股价的潜在影响 |
| **3.2 机构研报** | `【待补充】` 研报观点汇总、隐藏线索挖掘分析 | 基于「研报明细」及链接，可以使用 `curl` + `pdfplumber` 提取；须包含：各机构核心数据与观点、隐藏线索挖掘、目标价/评级、一致性判断及分歧点 |
| **3.3 行业个股新闻** | `【待补充】` 新闻汇总分析 | 基于「近期新闻」表，提炼关键信息、市场情绪及对公司的潜在影响 |
| **4.2 视觉分析** | `【待补充】`（可由 Agent 指派 subagent 执行） | 读取 `charts/<代码>_<市场>_kline.png`、阅读 `references/wave_structure_abc.md`；完成 ABC 三浪划分 → 四维打分 → 趋势结构得分与买点判断；输出均线/支撑压力/形态/MACD/成交量/关键信号 |
| **五、投研结论** | `投研结论需要基于以上分析人工撰写` | 基于以上分析撰写；须包含：五维交叉验证、综合评级、交易预案、操作建议、风险提示 |

### 3. 注意事项

#### 3.1 搜索工具使用方式
**Web Search**：使用内置的 `web_search` 工具

**Web Fetch工具**：
1. **网页内容**：直接使用内置的 `web_fetch` 工具

2. **PDF 内容**：使用 `curl` + `pdfplumber`（scrapling 不支持 PDF 格式）
```bash
  # 下载 PDF（注意：scrapling 不支持保存为 .pdf）
  curl -sL "https://pdf.dfcfw.com/pdf/xxx.pdf" -o /tmp/report.pdf
  
  # 验证文件类型（必须是 "PDF document"）
  file /tmp/report.pdf
  
  # 提取 PDF 文本内容
  python3 -c "import pdfplumber; [print(f'=== Page {i+1} ===\n' + (p.extract_text() or '')) for i,p in enumerate(pdfplumber.open('/tmp/report.pdf').pages)]"
```

**适用场景**：
- 网络搜索：使用 `web_search`
- 网页内容提取：使用 `web_fetch`
- 研报 PDF 提取：使用 `curl` + `pdfplumber`




#### 4.2 各分项的详细要求

**一、1.2 政策分析**
- 数据来源：`business_analysis.py` 产业链模板中的「行业深度分析-政策/周期」
- ⚠️ **【必须核验】** 需 Agent 通过 `web_search` 针对具体政策补充政策内容与深度解读
- 须包含：政策目标、适用时间、短期/中期影响、对公司的具体影响

**二、2.1 商业模式深度解析**
- 脚本会打出多块 `【待补充】`：盈利模式定位、产业链、商业模式五维评估
- 每块附有「建议搜索」关键词（如 `公司名 软件服务 产业链 上下游`）
- ⚠️ **【必须查阅】** 使用 `web_search` 按关键词补充；须覆盖：盈利模式、产业链、费用结构、产业链话语权、现金流健康度

**二、2.2 竞争格局全面评估**
- 脚本有「护城河与竞争壁垒」表（含建议搜索关键词）、「竞争分析待验证」提示
- ⚠️ **【必须查询】** 按表内关键词搜索补充：前五大客户、核心技术/专利、客户认证/合同、与竞争对手差异化
- 验证细分竞争对手、产业链关系、市场份额；财务指标是线索，业务实际为准

**二、2.3 市场预期深度分析**
- 脚本有「市场预期待补充」表：机构一致预期、订单/产能、概念/题材、估值锚定、业绩催化剂
- ⚠️ **【必须核验】**按表内建议搜索关键词使用 `web_search` 验证；须标注可信度（✅已验证/⚠️待验证/❓未证实）
- 未经验证不得作为投资依据

**三、3.1 近期公告汇总**
- 脚本输出「公告列表」及链接；`【待补充】` 公告汇总分析
- 重点分析：重大合同/订单、募集资金、资产收购出售、高管变动、股权激励、诉讼问询、业绩说明、分红送转
- ⚠️ **【必须核验】** 对公告的分析判断必须基于原文内容，禁止凭猜测下结论
- 查阅方式：通过公告链接访问原文，提取关键内容后分析
- 如无法获取原文，则不标注具体影响，标注"需进一步确认"

**三、3.2 机构研报**
- 脚本输出「研报明细」及链接；`【待补充】` 研报观点汇总、隐藏线索挖掘分析
- ⚠️ **【必须核验原始数据】** 使用`curl` + `pdfplumber` 提取原始研报PDF数据，禁止盲目相信二手信息
  - **提取方式**：
    - **PDF 研报**：使用 `curl` + `pdfplumber`
    - **网页研报**：使用 `web_fetch`
- **隐藏线索挖掘方法**（从财务数据中发现不易察觉的信号），例如：
  1. **库存周期**：对比前后年份存货变化（如 78亿→34亿），判断管理层对需求的预期
  2. **现金流拐点**：经营现金流从负转正，往往先于业绩拐点
  3. **负债/杠杆变化**：主动降杠杆反映财务审慎度
  4. **资本开支节奏**：判断产能扩张是激进还是稳健
  5. **产品升级周期**：如 iPhone 存储容量变化（128GB→256GB）

- **输出格式**：新增「📊 机构原始数据深度挖掘」表格，包含：线索 | 数据对比 | 解读

- ⚠️ **【必须包含】** 各机构核心观点、目标价/评级、一致性判断及分歧点
- ⚠️ **【关键发现】** 总结1-2条最重要的独立判断，标注「三重利好共振」等

**三、3.3 行业个股新闻**
- 脚本输出「近期新闻」表；`【待补充】` 新闻汇总分析
- 提炼关键信息、市场情绪及对公司的潜在影响

**四、4.2 视觉分析**
- K 线图会在运行research_report.py时自动生成并保存在 `charts/` 目录下，命名格式为 `<代码>_<市场>_kline.png`（如 `600519_SH_kline.png`），无需额外生成
- ⚠️ **必须**使用 `read` 工具读取 K 线图：`read charts/<代码>_<市场>_kline.png`
- ⚠️ **必须**依据 `references/wave_structure_abc.md` 做趋势结构判断：ABC 三浪划分 → 四维打分 → 趋势结构得分（0～100）与强弱结论 → 买点位置判断

**五、投研结论**
- 须包含：多维交叉验证、综合评级、交易预案、操作建议、风险提示



⚠️ **注意**：各分项最终需要包含一个精简版的小结结论，汇总分析结果。使用`> `语法，例如：
> **小节结论**：...

#### 4.4 关键原则

1. **框架闭环** - 宏观→基本面→消息面→技术面缺一不可
2. **商业模式优先** - 先理解怎么赚钱、护城河在哪
3. **竞争格局重实质** - 财务指标是线索，业务实际为准
4. **市场预期必查** - 高PE挖掘预期，低估值探讨催化
5. **公告研判必须基于原文** - 禁止凭猜测下结论，无法获取原文则标注"需进一步确认"
6. **研报观点多家验证** - 不迷信单一机构观点，一致性更可靠
7. **技术面视觉必做** - 必须读取K线图完成趋势结构视觉分析
8. **业绩时效性优先原则** - 所有资讯内容都必须考虑时效性，太久远的资讯早已被市场消化，不予参考
9. **Agent 强制迭代** - 报告生成后必须搜索验证并补充
10. **数据说话** - 用数据验证观点
11. **风险第一** - 盈亏比>2:1
12. **数据来源标注** - 所有数据标注来源
13. **事实为据** - 分析判断必须基于可查证的事实，禁止凭猜测下结论




#### 禁止行为

- ❌ 未经验证的消息作为投资依据
- ❌ 消息滞后过时的资讯作为投资依据
- ❌ 发现业绩下滑但不调整投资评级
- ❌ 对公告的分析判断不查阅原文，凭猜测下结论
- ❌ 技术面分析不读取K线图，凭感觉判断趋势结构
- ❌ 研报观点不查阅原文，凭标题或二手信息下结论
- ❌ 生成报告后不进行搜索验证和补充

### 5. 检查清单

完成研报前**必须**确认以下项：

**视觉分析**
- [ ] 已读取 K 线图 `charts/<代码>_SH或SZ_kline.png`（如 `600519_SH_kline.png`）
- [ ] 已阅读并依据 `references/wave_structure_abc.md` 做趋势结构判断（ABC 划分、趋势结构得分、强弱结论、买点位置）
- [ ] **趋势结构**维度：已按 `references/wave_structure_abc.md` 第「五、执行清单」顺序执行（标拐点→回撤/时间/量能/MACD 打分→汇总得分→买点结论）

**待补充项**
- [ ] 1.2 政策分析已补充（政策目标、适用时间、短中期影响、对公司影响）

- [ ] 3.1 公告汇总分析已补充
- [ ] 3.2 机构研报观点汇总已补充（核心观点、隐藏线索、目标价/评级、一致性及分歧点）

- [ ] 4.2 视觉分析已补充（趋势结构分析评分）

**验证项**

### 6. 输出文件说明

```
tushare-research/
├── raw_reports/      # 初始生成的研报（脚本 --save-md 输出）
├── reports/          # 补充后的研报（待补充项填充完成后）
├── charts/           # K线图 .png
├── references/       # 视觉分析文档
└── scripts/          # 分析脚本
```

| 文件夹 | 用途 |
|--------|------|
| **raw_reports/** | **初始生成**的研报：脚本 `--save-md` 输出，含「待补充」占位，需 Agent 或人工迭代补充 |
| **reports/** | **补充后**的研报：待补充项均已填充、视觉分析完成、投研结论撰写完成，可作为可交付版本 |

| 文件类型 | 命名格式（与脚本一致） |
|---------|------------------------|
| 初始研报 | `raw_reports/<代码>_深度研报_<YYYYMMDD>.md`（如 600519_深度研报_20260302.md） |
| 补充后研报 | `reports/<代码>_深度研报_<YYYYMMDD>.md` |
| K 线图 | `charts/<代码>_<市场>_kline.png`（代码中 `.` 换为 `_`，如 600519_SH_kline.png） |

**使用建议**
